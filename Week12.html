01 · Module 11

ปัญหาที่ Step Functions มาแก้ และ Step Functions คืออะไร

สรุปใน 1 ประโยค

Step Functions เป็น service orchestration ที่ทำให้เห็น workflow ของหลาย service ในที่เดียว มี retry และ log ทุกขั้น ได้ความคล่องตัวแน่นอนแต่ค่าใช้จ่ายเพิ่ม และ resilience ขึ้นกับการ config ของเรา

ปัญหา

  • ระบบแบบ Microservices / Distributed Application เอา AWS service หลายตัวมาทำงานร่วมกัน โดยมีตัวเชื่อมอย่าง API Gateway, SQS, SNS
  • เวลาระบบมีปัญหา ต้อง เปิดดูทีละ service เอง ระบบเล็กยังพอไหว แต่พอสเกลใหญ่จะไล่หาปัญหายากมาก
  • ทางแก้: ใช้ AWS Step Functions ทำให้ เห็น workflow ทั้งหมดในที่เดียว
Request ─► API Gateway ─► Lambda (Service 2) ─┬─ true  ─► บันทึกลง DynamoDB (Service 3)
                                              └─ false ─► แจ้งเตือนทางอีเมลด้วย SES (Service 4)

Step Functions คืออะไร

  • เป็น service orchestration สำหรับจัดการ workflow ของ AWS service ต่าง ๆ เช่น Lambda
  • ความสามารถหลัก: ทำงานแบบ automate มี เงื่อนไข มี trigger และ เรียงลำดับขั้นตอน ให้ / retry อัตโนมัติ เมื่อเกิด error / เก็บ log ทุกขั้นตอน ไว้ย้อนดูและวิเคราะห์
  • ข้อดี: agility และสเกลได้ดี, แก้ปัญหาได้เร็ว downtime น้อยลง, resilience, maintain ง่ายขึ้น
  • ข้อแลกเปลี่ยน: ค่าใช้จ่ายเพิ่มขึ้น
จุดที่ควรจำ
  • ความคล่องตัวเราได้แน่นอน แต่ resilience จะได้จริงหรือไม่ ขึ้นอยู่กับการออกแบบและ config ของเรา เช่นจะ retry กี่ครั้ง หรือขั้นไหนควรแจ้งให้คนเข้ามาดูแทนการ retry
  • ไม่มี Step Functions ก็ทำงานได้ แค่ไม่สะดวกและไม่เร็วเท่า

เสริม การ retry ตั้งที่ field Retry (เช่น MaxAttempts, IntervalSeconds, BackoffRate) และการจัดการเมื่อ retry ไม่สำเร็จตั้งที่ Catch ของแต่ละ state

แบบจำลอง

ระบบพัง — หาว่าพังที่ไหน

    จุดหลอกในข้อสอบ
    • "ใช้ Step Functions แล้ว resilience มาเอง" — ผิด ขึ้นกับการ config ของเรา
    • ข้อแลกเปลี่ยนคือ ค่าใช้จ่ายเพิ่มขึ้น ไม่ใช่ downtime เพิ่มหรือ maintain ยากขึ้น
    • ไม่มี Step Functions ก็ทำงานได้ แค่ไม่สะดวก
    02 · Module 11

    รูปแบบ workflow และการกำหนด State Machine

    สรุปใน 1 ประโยค

    workflow มี 4 รูปแบบ (Sequence, Parallel, Choice, Retry) นิยามเป็น state machine ด้วย JSON ภาษา ASL (StartAt, States, Type) หรือแบบ visual แล้วเจาะดูได้ว่า error เกิดที่ state ไหน

    รูปแบบความหมาย
    Sequenceทำ A เสร็จแล้วค่อยทำ B
    Parallelทำ 2 งานพร้อมกัน เสร็จแล้วค่อยไป C
    Branching (Choice)แยกทางตามเงื่อนไข true/false
    Retryลองใหม่เมื่อ fail
    • เรากำหนดเองว่ามี state / task อะไรบ้าง, transition จาก state ไหนไป state ไหน และ input/output ของแต่ละขั้น
    • มองเห็นภาพรวม (visualize) ได้ และ เจาะดูแต่ละ state ได้ว่า error เกิดที่ Lambda ตัวไหน ไม่ต้องเปิดทีละตัว
    • เขียนได้ 2 แบบ: JSON ด้วย Amazon States Language (ASL) หรือ แบบ visual ลากวาง
    • โครงสร้าง syntax มี StartAt, States และ Type ของแต่ละ state
    ดู graph คู่กับ ASL

    เลือกรูปแบบ แล้วคลิก state เพื่อดูบรรทัดใน JSON

      • 
      
    • state แรกระบุด้วย StartAt — Next คือ state ถัดไป, Type คือชนิด

    03 · Module 11 · ออกสอบบ่อย
    
  
    State Types
    
  
    สรุปใน 1 ประโยค
    Task ทำงานหนึ่งหน่วย, Choice แยกทาง, Fail/Succeed จบ, Pass ส่งต่อเฉย ๆ, Wait รอ, Parallel ทำหลาย branch พร้อมกัน, Map ทำซ้ำกับทุกรายการใน input
    
  
    
    
    Stateหน้าที่
    
    
      
    Taskหน่วยงานเดียว (single unit of work) เช่นเรียก Lambda, EC2, ECS
    
      
    Choiceแยกทางตามเงื่อนไข (yes/no, true/false)
    
      
    Failจบแบบล้มเหลว (stop)
    
      
    Succeedจบแบบสำเร็จ
    
      
    Passส่ง input ต่อไปโดยไม่ทำงานอะไร
    
      
    Waitรอเวลา เช่นรอให้ process เสร็จก่อนไปขั้นต่อไป
    
      
    Parallelสร้าง หลาย branch ที่ทำงานพร้อมกัน
    
      
    Mapวนทำซ้ำกับแต่ละรายการใน input (เสริม อาจารย์ไม่ได้อธิบายละเอียด)
    
        
  
    
  
    
    
    Parallel
    • branch ต่างกัน ทำพร้อมกัน
    • จำนวน branch คงที่ ตามที่เขียนไว้
    • เช่น ตรวจสต็อก + ตรวจบัตร พร้อมกัน
    
    
    Map
    • ขั้นตอน เดียวกัน ทำกับ ทุกรายการ ใน array
    • จำนวนรอบขึ้นกับ input
    • เช่น ส่งอีเมลยืนยันให้ลูกค้าทุกคน
    
  
    
  
    
    
    จับคู่
    สถานการณ์นี้ใช้ state type ไหน
    
    
    
      
    
      
    
    
    
  
    
  
    จุดหลอกในข้อสอบ
    
      
      
    • Pass ส่งต่อทันทีโดยไม่ทำอะไร / Wait รอเวลาก่อนไปต่อ
      • 
      
    • ทุกรายการใน array → Map (ไม่ใช่ Parallel และไม่ใช่สร้าง Task 100 ตัว)
      • 
      
    • จบแบบล้มเหลว = Fail / จบแบบสำเร็จ = Succeed
      •

    Standard vs Express Workflow
    
  
    สรุปใน 1 ประโยค
    Standard (~2,000/วินาที) รันนานและ audit ได้ คิดเงินต่อ state transition ส่วน Express (~100,000/วินาที) รับงาน volume สูงที่รันไม่เกิน 5 นาที คิดตาม request + duration
    
  
    
    
    StandardExpress
    
    
      
    Rate~2,000 executions/วินาที~100,000 executions/วินาที
    
      
    คิดเงินตามจำนวน state transitionจำนวน request + ระยะเวลา (duration)
    
      
    เหมาะกับงานที่รันยาว ๆ (long-running) และต้อง audit ได้งาน high-volume / event processing
    
      
    ระยะเวลารันนาน (เสริม สูงสุด 1 ปี)ไม่เกิน 5 นาที
    
        
  
    
  
      
    
    • อาจารย์เน้นว่า ไม่ใช่ทุกงานต้องใช้ Express เพราะยิ่ง performance สูง ราคาก็ยิ่งสูง
      • 
    
    • เสริม Standard เป็นแบบ exactly-once ส่วน Express แบบ asynchronous เป็น at-least-once (แบบ synchronous เป็น at-most-once)
      • 
    
    • Step Functions มี API ให้เรียกจากโค้ดได้ ลองดูใน lab
      • 
  
    
  
    
    
    ช่วยเลือก
    งานนี้ใช้ Standard หรือ Express
    
    
    
      
    
        
    
        
    
      
    
      
      
    
      
    
    
    
  
    
  
    จุดหลอกในข้อสอบ
    
      
      
    • Express ไม่เกิน 5 นาที (15 นาทีคือ Lambda, 1 ปีคือ Standard)
      • 
      
    • "คิดตาม transition" = Standard / "คิดตาม request + duration" = Express
      • 
      
    • งานยาวและต้อง audit → Standard / volume สูงมากและสั้น → Express
      • 
    
    
  
    
  
    
  
    

    



    
  
    06 · Module 11
    
  
    Case study: Amazon Prime Video (2023)
    
  
    สรุปใน 1 ประโยค
    เมื่อ volume สูงมาก การจ่ายต่อ transition ของ Step Functions แพงกว่า EC2 ที่จ่ายคงที่ Prime Video จึงย้ายฟีเจอร์หนึ่งไปเป็น monolith บน EC2 และลด cost ได้ราว 90% — ต้องประเมินความคุ้มค่าเสมอ
    
  
      
    
    • ฟีเจอร์หนึ่งเดิมใช้ distributed microservices ร่วมกับ Step Functions แล้ว ย้ายไปเป็น monolith บน EC2 ทำให้ ลด cost ได้ราว 90%
      • 
    
    • สาเหตุ: ผู้ใช้เยอะมาก มี transition เยอะ และ Step Functions คิดเงินทุกครั้งที่ execute ขณะที่ EC2 จ่ายคงที่ 24 ชม. x 7 วัน
      • 
    
    • ตอนนี้บทความต้นฉบับถูกลบไปแล้ว
      • 
    
    • บทเรียน: ต้อง ประเมินความคุ้มค่า ระหว่างความคล่องตัวที่ได้กับค่าใช้จ่ายที่เพิ่มขึ้น ถ้าอธิบายเหตุผลได้ชัด บริษัทเอกชนมักยอมจ่าย แต่หน่วยงานรัฐส่วนใหญ่อยากได้ของถูก
      • 
  
    
  
    
    
    คำนวณ
    จุดคุ้มทุน: จ่ายต่อ transition vs EC2 คงที่
    
    
    
      
    
        
    
        
    
        
    
      
    
      
    
      
      
      
      Step Functions คิดที่อัตรา Standard ราว $0.025 ต่อ 1,000 state transition เสริม (ไม่รวม free tier) ส่วนค่า EC2 เป็นตัวเลขสมมติเพื่อเปรียบเทียบแนวคิด
      
    
      
  
      
  
      การบ้าน Module 11: Lab 1 อัน + Knowledge Check
      
  
      จุดหลอกในข้อสอบ

        • 
      
      • เหตุผลคือ จ่ายต่อ execution/transition เทียบกับ EC2 ที่จ่ายคงที่ ไม่ใช่เพราะ EC2 ฟรี

      Secure Network Connection: TLS และ Certificate
      
  
      สรุปใน 1 ประโยค
      TLS (ชื่อเดิม SSL) ใช้กับ HTTPS โดย browser ตรวจ certificate ที่ CA รับรองว่าเว็บเป็นของจริง แล้วแลก session key เพื่อเข้ารหัส — certificate ต้อง renew เสมอ ซึ่ง ACM ช่วยจัดการให้
      
  
      แอปจะปลอดภัยได้ต้องดูหลายองค์ประกอบ ไม่ใช่แค่ตัวแอป Module นี้มี 3 หัวข้อ: Secure Network Connection, Authentication ด้วย STS และ Amazon Cognito
      
  
        
    
      • TLS (Transport Layer Security) ใช้กับ HTTPS ส่วน SSL (Secure Sockets Layer) เป็นชื่อเดิม ปัจจุบันใช้ TLS เป็นหลัก
        • 
    
      • ทำไมต้องมี certificate: เพื่อ ยืนยันว่าเว็บหรือ service ที่เราคุยด้วยเป็นของจริง ก่อนจะใส่ username/password การยืนยันทำผ่าน CA (Certificate Authority)
        • 
    
      • อาจารย์ยกตัวอย่างเว็บข้อมูลที่ถามรหัสผ่านโดยไม่มีเหตุผล ซึ่งควรสงสัยไว้ก่อน
        • 
    
      • ขั้นตอน TLS: browser (client) กับ server ตรวจ certificate แล้ว แลก session key เพื่อใช้เข้ารหัส
        • 
  
      
  
      การจัดการ certificate
      
  
        
    
      • ต้อง renew อยู่เรื่อย ๆ ถ้าหมดอายุ browser จะเตือนว่า "อันตราย" แล้วผู้ใช้จะไม่กล้าเข้าเว็บ
        • 
    
      • AWS Certificate Manager (ACM) ช่วยจัดการ certificate ให้ตาม policy และ config ที่เรากำหนด
        • 
    
      • เสริม public certificate ของ ACM ที่ผูกกับบริการที่ integrate กัน (เช่น ELB, CloudFront, API Gateway) renew ให้อัตโนมัติ
        •

        • จัดการ certificate → ACM (ไม่ใช่ STS หรือ Cognito)

        08 · Module 12
        
  
        TLS Termination ที่ ALB vs End-to-End Encryption ด้วย NLB
        
  
        สรุปใน 1 ประโยค
        ใส่ certificate ที่ ALB เพื่อย้ายภาระเข้ารหัสออกจาก EC2 แต่ช่วง ALB → EC2 ใน VPC เป็น plaintext ถ้าต้องเข้ารหัสตลอดทางต้องใช้ NLB และจัดการ certificate ที่ server เอง
        
  
        
    
        รูปแบบที่ 1: TLS Termination ที่ ALBรูปแบบที่ 2: End-to-End Encryption
        
    
      
        เส้นทางClient → Internet Gateway → ALB → EC2Client → Internet Gateway → NLB → EC2
        
      
        certificate อยู่ที่ALB (ALB เป็นคน negotiate TLS กับ client)server (ต้องจัดการ certificate เอง)
        
      
        ข้อดีย้ายภาระการเข้ารหัสออกจาก EC2เข้ารหัสตลอดทาง
        
      
        ข้อแลกALB → EC2 ใน VPC เป็น plaintext — หลายกรณีรับได้เพราะอยู่ภายใน VPCEC2 ทำงานเข้ารหัสเองและดูแล certificate เอง
        
      
        ใช้เมื่อกรณีทั่วไปต้องการความปลอดภัยสูงมาก กลัวภายในถูก compromise — ใช้ ALB ไม่ได้ ต้องใช้ NLB
        
            
  
        
  
        เสริม ALB ส่งต่อไปยัง target ด้วย HTTPS (re-encrypt) ได้ แต่ ALB ยังต้องถอดรหัสก่อนเสมอ ถ้าต้องการไม่มีจุดถอดรหัสระหว่างทางเลยต้องใช้ NLB แบบ TCP passthrough — ในข้อสอบให้ยึดตามที่อาจารย์สอน
        
  
        
    
        เปรียบเทียบ
        เส้นทางของข้อมูลและใครอ่านได้
        
    
        
      
        
        
        
          
          
        
        
        
      
        
      
        
      
        
      
        
      
          
    
          
  
          
  
          จุดหลอกในข้อสอบ
    
            
      
          • TLS termination ที่ ALB → ช่วง ALB → EC2 เป็น plaintext (ไม่ใช่เข้ารหัสตลอดทาง)
            • 
      
          • end-to-end ตามที่อาจารย์สอน → NLB + certificate ที่ server
            • 
      
          • เหตุผลที่รับได้: plaintext อยู่ ภายใน VPC
            • 
    
          
  
          
  
          
  
          

          



          
  
          09 · Module 12
          
  
          Authentication ด้วย AWS STS
          
  
          สรุปใน 1 ประโยค
          IAM user ใช้ long-term credential ส่วน IAM role และผู้ใช้ภายนอกใช้ temporary credential จาก STS ที่หมดอายุเอง จึงจำกัดความเสียหายเมื่อรั่ว — ผู้ใช้ภายนอกต้อง assume role เสมอ และดูประวัติได้ใน CloudTrail
          
  
          
    
          คำความหมาย
          
    
      
          Authenticationการ พิสูจน์ตัวตน
          
      
          Authorizationการดู policy ว่า ทำอะไรได้บ้าง
          
              
  
          
  
            
    
          • Identity Provider (IdP): แบบตั้งเอง (LDAP, Active Directory), แบบ third-party หรือใช้ Identity Broker เป็นตัวกลางไปขอ temporary credential มาให้
            • 
    
          • IAM User ใช้ long-term credential (console password หรือ access key + secret access key) / IAM Role ใช้ temporary credential จาก STS
            • 
    
          • ผู้ใช้จากภายนอก (federated) ยืนยันตัวกับ IdP ได้ token แล้วใช้ token ไป assume role ที่ IAM กำหนดไว้
            • 
    
          • มาตรฐาน: SAML, OpenID Connect (OIDC), JWT
            • 
    
          • STS สร้าง short-lived credential ที่หมดอายุแล้วใช้ต่อไม่ได้ เช่น Learner Lab ให้ access key, secret key และ session token ใช้ได้ประมาณ 4 ชม. กด Start ใหม่ STS ออก token ใหม่ให้
            • 
    
          • Identity ที่ใช้ STS ได้ (ตามที่อาจารย์ไล่): IAM user, IAM role, IAM user group, Federated identity, AWS Service, AWS account root user — เสริม ตามเอกสาร AWS IAM group ไม่ใช่ principal จึงขอ credential เองไม่ได้ และไม่ควรใช้ root user ทำงานประจำ
            • 
  
          
  
          ทำไมต้องใช้ temporary credential — ตัวอย่างตึกออฟฟิศ
          
  
          
    
          สมัยก่อน
          แลกบัตรแล้วไปได้ ทุกชั้น
          
    
          ต่อมา
          บัตรแตะลิฟต์ได้ เฉพาะชั้นที่จะไป
          
    
          ปัจจุบัน
          QR code ใช้ได้ครั้งเดียว ปลอมยากขึ้น — แต่ใช้ยากขึ้น (เพื่อนอาจารย์ลืมพาสปอร์ตเลยออกจากตึกเองไม่ได้)
          
  
          
  
          
    
          แบบจำลอง
          Flow ของ STS และ credential รั่ว
          
    
          
      
          
        
          
          
          
        
          
        
      
          
      
          
      
            
      
            ถ้า credential รั่วไปถึงผู้ไม่หวังดี
            
      
            
        
        
      
            
      
            
      
            
      
            
    
            
  
            
  
            จุดหลอกในข้อสอบ
    
              
      
            • Authentication = พิสูจน์ตัวตน / Authorization = ดู policy ว่าทำอะไรได้
              • 
      
            • IAM user = long-term / IAM role = temporary (ช้อยหลอกชอบสลับ)
              • 
      
            • มาตรฐาน federation = SAML, OIDC, JWT (TLS/SSL ไม่ใช่)
              • 
      
            • ผู้ใช้ภายนอก ต้อง assume role เสมอ / ดูประวัติการเรียก → CloudTrail
              • 
    
            
  
            
  
            
  
            

            



            
  
            10 · Module 12
            
  
            Amazon Cognito: User Pool และ Identity Pool
            
  
            สรุปใน 1 ประโยค
            User Pool เป็น directory สำหรับ sign-up/sign-in ที่ให้ JWT 3 ตัว (ID, access ถูก sign; refresh ถูก encrypt) ส่วน Identity Pool เป็น broker ที่ให้ temporary AWS credential ไปเรียก AWS service โดยตรง
            
  
            Cognito เป็น fully managed service สำหรับ authentication และ user management ของ web/mobile app มี 2 แบบ
            
  
            User Pool (directory ของผู้ใช้)
            
  
              
    
            • รองรับ sign-up / sign-in มี หน้า login สำเร็จรูป (hosted web UI) และ customize ได้
              • 
    
            • ล็อกอินผ่าน Amazon, Google, Facebook, SAML และ OIDC ได้
              • 
    
            • Security features: ตรวจรหัสผ่านที่ เคย leak / compromised แล้วเตือนผู้ใช้, ยืนยันตัวตนทางโทรศัพท์หรืออีเมล, MFA และ Adaptive Authentication, ทำ Custom Authentication Workflow ด้วย Lambda
              • 
  
            
  
            
    
            Token (JWT)หน้าที่การป้องกัน
            
    
      
            ID tokenบอกว่า เป็นใคร และได้รับอนุญาตแล้วsign
            
      
            Access tokenบอกว่า ทำอะไรได้บ้างsign
            
      
            Refresh tokenใช้ ต่ออายุ การใช้งานencrypt
            
                
  
            
  
            Identity Pool (Federated Identities)
            
  
              
    
            • ทำหน้าที่คล้าย broker ให้ temporary AWS credential กับผู้ใช้ เพื่อ เข้าถึง AWS service โดยตรง
              • 
    
            • ใช้เมื่อ มี IdP อยู่แล้ว (SAML, OIDC, Google, Facebook หรือแม้แต่ Cognito User Pool) และ ไม่ต้องสร้าง user pool ใหม่
              • 
    
            • เสริม รองรับผู้ใช้แบบ guest (unauthenticated) ได้ด้วย โดยให้สิทธิ์ผ่าน IAM role ที่จำกัดกว่า
              • 
  
            
  
            
    
            ลองเล่น
            Cognito explorer
            
    
            
      
            
        
        
        
      
            
      
            
        
            
        
            
        
            
          
          
          
        
            
        
            
        
            กด Sign in เพื่อดู flow: app → User Pool → JWT → API Gateway validate → Lambda
            
      
            
      
            
        
            
        
            
        
            
        
            flow: sign in กับ User Pool (หรือ IdP อื่น) → ขอ credential จาก Identity Pool → ได้ temporary AWS credential → เรียก S3 / DynamoDB โดยตรง
            
      
            
      
            
    
            
  
            
  
            จุดหลอกในข้อสอบ
    
              
      
            • User Pool → JWT / Identity Pool → temporary AWS credential (ช้อยหลอกมักสลับ)
              • 
      
            • ID และ access token ถูก sign / refresh token ถูก encrypt
              • 
      
            • แอปต้องเรียก S3/DynamoDB โดยตรง → Identity Pool (อย่าฝัง access key ในแอป)

              สรุปสั้นก่อนสอบ
              
  
              
  
              
    
              Step Functions
              • orchestrate workflow ของ microservices
              • เห็นภาพรวม + retry + log ทุกขั้น
              • ข้อแลก: cost เพิ่ม
              
    
              Resilience
              • agility ได้แน่
              • resilience ขึ้นกับการ config (retry กี่ครั้ง / ให้คนดู)
              
    
              Workflow
              • Sequence, Parallel, Choice, Retry
              • ASL (JSON): StartAt, States, Type
              
    
              State types
              • Task, Choice, Fail, Succeed
              • Pass, Wait, Parallel, Map
              
    
              Standard vs Express
              • Standard: ~2,000/s, ต่อ transition, ยาว + audit
              • Express: ~100,000/s, request + duration, ≤ 5 นาที
              
    
              Prime Video
              • ย้ายออกจาก SF → monolith บน EC2
              • ลด cost ~90% เพราะจ่ายต่อ execution
              
    
              TLS
              • SSL ชื่อเดิม → TLS (HTTPS)
              • certificate ยืนยันผ่าน CA
              • ตรวจ cert → แลก session key
              • ACM จัดการ certificate
              
    
              ALB vs NLB
              • ALB termination: offload EC2, ใน VPC plaintext
              • NLB: end-to-end, cert ที่ server
              
    
              STS
              • IAM user = long-term
              • IAM role = temporary (STS)
              • รั่วแล้วเสียหายจำกัด · ภายนอกต้อง assume role
              
    
              Federation
              • SAML, OIDC, JWT
              • ประวัติการเรียก → CloudTrail
              • Learner Lab ~4 ชม.
              
    
              Cognito User Pool
              • sign-up / sign-in
              • JWT 3 ตัว: ID, access (sign), refresh (encrypt)
              
    
              Cognito Identity Pool
              • broker → temporary AWS credential
              • เรียก AWS service โดยตรง
              
  
              
  
              ตัวอย่างการตอบแบบสั้นตรงจุด
              
  
              "Step Functions เป็น orchestration ที่ทำให้เห็น workflow ของ microservices ในที่เดียว มี retry และ log ทุกขั้น นิยามด้วย ASL ที่มี StartAt, States และ Type เช่น Task, Choice, Parallel, Map แต่ค่าใช้จ่ายเพิ่ม จึงต้องดูความคุ้มค่าแบบเคส Prime Video งานยาวและต้อง audit ใช้ Standard ที่คิดเงินต่อ transition งาน volume สูงไม่เกิน 5 นาทีใช้ Express ด้านความปลอดภัย ใส่ certificate ที่ ALB เพื่อ offload TLS แต่ช่วงใน VPC เป็น plaintext ถ้าต้องการเข้ารหัสตลอดทางใช้ NLB และใช้ ACM ดูแล certificate ใช้ STS ออก temporary credential เพื่อจำกัดความเสียหาย และใช้ Cognito User Pool ทำ login ได้ JWT 3 ตัว ส่วน Identity Pool ให้ temporary AWS credential ไปเรียก service โดยตรง"
